# Domain Documentation

## Layout

Single-context. One `CONTEXT.md` at the repo root covers the entire project.

## Rules

### Reading

- Always read `CONTEXT.md` at the repo root before making architectural or domain decisions.
- If an `docs/adr/` directory exists, read the relevant ADRs before proposing changes to established patterns.

### Writing

- New ADRs go in `docs/adr/` with the format `NNNN-<title>.md`.
- `CONTEXT.md` should be updated when the project's scope, architecture, or key decisions change.
